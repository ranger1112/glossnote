# 0.6.0 实施方案

> 对应技术方案：[0.6.0-plan.md](0.6.0-plan.md)
> 日期：2026-11-09
> 状态：已实施；T6 真实 MCP 客户端验收已通过（Claude Code 2.1.319，2026-11-09），随 0.5.0 发版后再发 0.6.0

## 1. 交付范围

0.6.0 分两条主线，共用现有 SQLite、sidecar、标注与阅读链路：

- **P0 MCP 只读接入**：应用内 loopback HTTP MCP，默认关闭；外部 Agent 可列出文档、读取元数据、搜索/读取标注、读取书签；正文搜索与正文读取由 `exposeText` 单独开启。
- **P1 文档笔记**：每篇文档一份 `.glossnote/notes/<docId>.md`；侧栏编辑/预览/专注编辑；`[[annotation]]` / `[[doc]]` / `[[page]]` 引用可跳回原文；书库搜索与 Markdown 导出接入笔记；MCP 提供 `get_notes`。

不在 0.6.0 内：MCP 写入、ACP/本地 Agent 托管、deep link、笔记 FTS5、跨设备笔记合并、版面分析、移动端。

**前置约束**：0.5.0 的桌面冒烟与发版仍是独立门禁；0.6.0 可以并行开发，但发版顺序必须是 0.5.0 → 0.6.0。开发期间不提前改版本号。

## 3. 关键细化决策

### 3.1 页码统一 1 基

内部存储与前端仍是 0 基；**MCP 对外全部 1 基**，在 `mcp/mapping.rs` 统一转换：

- `list_documents.lastPage`、`get_document.bookmarks[].page`、`search_annotations.page`、`list_annotations.page`、`search_pages.page`、`read_document_text.pageStart/pageEnd` 均为 1 基。
- 资源 URI `glossnote://doc/<id>?page=N` 的 `N` 为 1 基。
- 笔记链接 `[[page:N]]`、`[[doc:<id>#page=N]]` 同样是 1 基，与阅读器顶栏页码一致。

### 3.2 MCP 输出与错误

- 每个工具声明 `outputSchema`，成功返回 `structuredContent`，同时保留一段简短 `text` 说明。
- 业务错误（文档不存在、正文未开启、参数越界）返回 `CallToolResult.isError=true` + 可操作文本；JSON-RPC error 只用于未知工具、非法 JSON、未授权。
- 列表默认 50、上限 200；`limit<=0` 回退默认；`offset<0` 按 0。
- 所有 `docId` 必须能在索引中查到；`annotationId` 必须属于该文档；不读取任意文件路径。
- 工具只读：不提供 `write_annotation`、`append_note`、`delete_document`。
- DB 查询放在 `spawn_blocking`，锁只在阻塞任务内持有，绝不跨 `.await`。

### 3.3 笔记 revision 与保存结果

- `revision`：文件不存在时为 `""`；存在时为 UTF-8 内容的 sha256 小写十六进制。
- `updatedAt`：文件 mtime 毫秒；不存在为 `0`。
- 保存前比较 `expectedRevision`；不一致返回冲突，不覆盖。进程内用 `AppState.note_write` 串行化保存，避免两个防抖请求同时通过检查。
- 空内容（`trim().is_empty()`）删除文件，`revision` 回到 `""`，避免空文件堆积。
- 单文件上限 2 MB（按 UTF-8 字节），读取与写入都检查。
- 命令返回类型化结果，而不是靠错误字符串判断冲突：

```rust
#[derive(Serialize)]
#[serde(rename_all = "camelCase", tag = "status")]
pub enum NoteSaveOutcome {
    Saved { note: NoteFile },
    Conflict { current: NoteFile },
}
```

### 3.4 笔记引用

- 只支持四种写法：`[[annotation:<id>]]`、`[[doc:<id>]]`、`[[doc:<id>#page=N]]`、`[[page:N]]`。
- 解析器是纯函数；格式不合法或目标不存在时按普通文本渲染，不抛异常。
- `[[annotation:id]]` 的目标解析需要跨文档查询，新增 `resolve_note_links` 命令一次返回标注与文档的轻量信息；前端按 300 ms 防抖解析，只在预览时请求。
- 点击 `[[annotation]]` 时打开目标文档、切到「标注」页签并复用现有 `jumpTo(annotation)` 聚焦；文档加载是异步的，用 `pendingAnnotationRef` 在 `doc + annotations` 就绪后消费，4 秒未就绪则提示目标不存在。

### 3.5 笔记 UI 状态归属

- `NotePanel` 自己持有编辑状态、保存队列与专注面板；App 只通过 `ref.flush()` 在切文档/关文档前落盘。
- 笔记页签在侧栏内始终挂载，非当前页签用 `hidden` 隐藏，避免切页签丢未保存内容。
- 专注编辑用 `createPortal` 挂到 `document.body`，复用同一份状态，不复制编辑器。
- 保存失败/冲突的提示留在面板内，不用全局消息覆盖；切换文档被 flush 阻止时才用全局消息说明原因。

## 5. M0：rmcp/axum spike

### 目标

在写业务代码前确认三件事：

1. `rmcp 3.9` 能在 Tauri 的 tokio 运行时里启动/关闭 Streamable HTTP 服务。
2. `#[tool_router]` / `#[tool]` 能生成工具列表、参数 schema 与 `structuredContent`。
3. Windows 打包无 OpenSSL/额外 DLL 依赖，体积增量可接受。

### 做法

- 在 `%TEMP%\glossnote-mcp-spike` 建独立 crate，不提交。
- 最小依赖：

```toml
rmcp = { version = "3.9", features = ["transport-streamable-http-server"] }
axum = "0.8"
tokio = { version = "1", features = ["net", "sync", "time"] }
```

- 实现一个 `list_documents` 假工具，bind `127.0.0.1:0`，用 `curl` 验证：
  - `initialize` 返回 `serverInfo` 与 capabilities。
  - `notifications/initialized` 不报错。
  - `tools/list` 包含工具与 `inputSchema`。
  - `tools/call` 返回 `structuredContent`。
  - 发送关闭信号后端口可重新 bind。
- 记录 `StreamableHttpService::new`、session manager、config 的实际类型名；M0 结束后把结论补到本文档「M0 结论」。

### 回退门槛

出现以下任一情况就回退手写 JSON-RPC：

- rmcp 无法在 Tauri 进程内启停，或引入无法接受的运行时/打包问题。
- 工具 schema/结构化输出无法满足上述协议面。
- 关闭后端口不能释放，或需要长期后台线程。

回退实现仍放在 `mcp/server.rs`，只支持 `initialize`、`notifications/initialized`、`ping`、`tools/list`、`tools/call`、`resources/list`、`resources/read`；至少用 Claude Desktop 或 Cursor 做一次真实连接验证。

### M0 结论

- `rmcp 3.9.0` + `axum 0.8.9` 在 Tauri 2 的 tokio 运行时中可直接使用；`StreamableHttpService` + `LocalSessionManager` 挂载 `/mcp`，工具宏生成 `inputSchema`/`outputSchema`，`Json<T>` 返回 `structuredContent`。
- `StreamableHttpServerConfig` 自带 `allowed_hosts`、`enforce_origin_validation`、`max_request_body_bytes`，与 token 路径中间件组合即可满足 v1 安全边界；无需自定义 HTTP 栈。
- 关闭使用 oneshot + `CancellationToken`，真实应用冒烟确认端口释放；未回退手写 JSON-RPC。
- 真实应用冒烟：8 个工具、2 个资源、正文开关、token/Origin/413 边界均通过 `curl` 验证；T6 已用本机 Claude Code 2.1.319 通过 `--mcp-config` 连接隔离沙箱，8 个工具全部调用成功，正文关闭时两个正文工具均返回可操作错误。

## 6. M1：MCP 设置与生命周期

### 改动文件

- `src-tauri/src/settings.rs`
- `src-tauri/src/state.rs`
- `src-tauri/src/mcp/mod.rs`（新增）
- `src-tauri/src/main.rs`
- `src-tauri/Cargo.toml`

### 设置模型

```rust
#[derive(Serialize, Deserialize, Clone, Debug)]
#[serde(rename_all = "camelCase")]
pub struct McpSettings {
    #[serde(default)]
    pub enabled: bool,
    #[serde(default = "default_mcp_port", deserialize_with = "deserialize_mcp_port")]
    pub port: u16,
    #[serde(default)]
    pub token: String,
    #[serde(default)]
    pub expose_text: bool,
}
```

- 默认：`enabled=false`、`port=8765`、`token=""`、`exposeText=false`。
- `AppSettings` 增加 `#[serde(default)] pub mcp: McpSettings`。
- `port` 用容错反序列化：非法值回退 8765，避免一个手改坏的端口让整个 `settings.json` 被判损坏、连带丢失 `libraryDir`。
- 加载后 `normalize()`：端口钳制到 `1024..=65535`；token 只接受 `[A-Za-z0-9_-]{16,128}`，否则清空，启用时重新生成。
- 生成 token：`getrandom::fill(&mut [0u8; 32])` 后转 64 位十六进制。关闭时保留 token，重置时才换。

### 运行时状态

```rust
pub struct McpConfig {
    pub enabled: bool,
    pub port: u16,
    pub token: String,
    pub expose_text: bool,
}

pub struct McpRuntime {
    pub port: u16,
    pub shutdown: tokio::sync::oneshot::Sender<()>,
    pub task: tauri::async_runtime::JoinHandle<()>,
}

pub struct McpState {
    pub config: McpConfig,
    pub runtime: Option<McpRuntime>,
    pub last_error: Option<String>,
}
```

- `AppState` 增加 `pub mcp: Mutex<McpState>`。
- 启动：先 `tokio::net::TcpListener::bind(("127.0.0.1", port))`，成功后再 `axum::serve`；绑定失败只写 `last_error`，不阻塞应用启动。
- 关闭：发送 oneshot，`tokio::time::timeout(2s, task)` 等待退出；超时只记日志，不让 UI 卡死。
- `mcp_set_enabled(true)` 先保存 `enabled=true`，再尝试启动；启动失败保留 `enabled=true` 供下次重试。token 为空时生成并保存。
- `mcp_set_port` 在运行中先停再起；启动失败同样保留新端口与错误状态。
- `mcp_set_expose_text` 只更新共享配置，不重启。
- `mcp_reset_token` 无论开关状态都生成并保存新 token；运行中重启服务。
- 所有设置命令串行化 `settings.json` 的读改写（复用 `AppState` 的锁或新增 `settings_write: Mutex<()>`）。

### 命令

```rust
#[tauri::command] async fn mcp_status(app: AppHandle) -> McpSettingsView;
#[tauri::command] async fn mcp_set_enabled(app: AppHandle, enabled: bool) -> Result<McpSettingsView, String>;
#[tauri::command] async fn mcp_set_port(app: AppHandle, port: u16) -> Result<McpSettingsView, String>;
#[tauri::command] async fn mcp_set_expose_text(app: AppHandle, expose_text: bool) -> Result<McpSettingsView, String>;
#[tauri::command] async fn mcp_reset_token(app: AppHandle) -> Result<McpSettingsView, String>;
```

`McpSettingsView`（前端 `types.ts` 同名）：

```ts
export interface McpSettingsView {
  enabled: boolean;
  port: number;
  exposeText: boolean;
  running: boolean;
  actualPort: number | null;
  error: string | null;
  url: string;          // 未启用或 token 为空时为空串
  configJson: string;   // 可直接粘贴的客户端配置
  tokenSet: boolean;
}
```

- 启用、改端口或重置 token 导致启动失败时返回 `Ok(view)`，把错误放进 `view.error`，让设置页展示而不是弹异常。
- 参数错误（端口 <1024、>65535）返回 `Err`。
- 启动时若 `enabled=true`，`main.rs` 在 `manage(AppState)` 之后 `mcp::spawn_start(handle)`；成功/失败都写回 `McpState`，设置页轮询状态。

### 测试

- `McpSettings` 默认值、容错端口、token 校验与 round-trip。
- `start_on(listener)` 用端口 0 启动，返回实际端口；stop 后同一端口可重新 bind。
- 非 loopback 地址不可配置（代码只 bind `127.0.0.1`）。
- 关闭后 `runtime=None`；重复 stop 幂等。
- 配置 JSON 包含 `/mcp/<token>`，不含其他敏感字段。

## 7. M2：MCP 协议与只读工具

### 模块

```text
src-tauri/src/mcp/
├── mod.rs        # 设置、生命周期、命令、AppState 交互
├── server.rs     # axum 路由、token/Origin 校验、rmcp 挂载
├── tools.rs      # 工具定义、参数校验、分发
└── mapping.rs    # DB 行 -> MCP 结构化结果（页码 +1 等）
```

`server.rs` 只做协议适配；工具逻辑集中在 `tools.rs`，这样回退到手写 JSON-RPC 时只换传输层。

### 路由与安全

- 只 bind `127.0.0.1`，端点 `POST /mcp/<token>`；GET/DELETE 由 Streamable HTTP 客户端使用。
- 中间件校验：
  - 路径必须精确等于 `/mcp/<token>`，否则 404（不暴露 token 是否正确）。
  - 任何请求带 `Origin` 头 → 403，阻止浏览器页面通过 localhost 访问。
  - `DefaultBodyLimit::max(1 MB)`。
  - 可选加固：`Host` 只接受 `127.0.0.1:<port>` / `localhost:<port>`；放在 M7，M2 先保证 token + Origin。
- 不添加 CORS 允许层；响应不包含 CORS 头。
- 服务端信息：`name="glossnote"`，`version=env!("CARGO_PKG_VERSION")`。

### 工具实现

所有工具先做参数校验，再通过 `tools::execute(conn, root, expose_text, name, args)` 调用；`execute` 是同步函数，便于单测。异步包装只负责取锁与 `spawn_blocking`。

| 工具 | 参数 | 返回要点 |
| --- | --- | --- |
| `list_documents` | `query?`、`kind?`、`limit?`、`offset?` | `items[]`：id、name、kind、title、author、pageCount、annotationCount、lastPage；`total`、`limit`、`offset` |
| `get_document` | `docId` | 元数据、bookmarks、annotationCount、lastPage、sourceUrl（仅 http/https）；不返回本地 path/sourcePath |
| `search_annotations` | `query`、`docId?`、`limit?` | docId、docName、annotationId、page、quote、body、color、kind、tags |
| `list_annotations` | `docId`、`page?`、`kind?`、`color?`、`limit?` | 当前文档标注；`total` |
| `get_annotation` | `docId`、`annotationId` | 单条完整内容（不含 anchor 坐标） |
| `search_pages` | `query`、`docId?`、`limit?` | 正文片段；需要 `exposeText` |
| `read_document_text` | `docId`、`pageStart?`、`pageEnd?`、`maxChars?` | 分页正文；需要 `exposeText` |
| `get_notes` | `docId` | text、updatedAt、revision、exists（M6） |

参数约束：

- `query` 去空白后为空 → 空结果或参数错误（搜索类返回空结果，避免 Agent 反复试错）。
- `kind` 只接受 `pdf|txt|html|epub`；`color` 只接受 `yellow|green|blue|pink`；`kind`（标注）只接受 `highlight|underline|strikethrough`。
- `read_document_text`：`pageStart` 默认 1；`pageEnd` 默认 `min(pageStart+9, pageCount)`；`pageEnd < pageStart` 返回参数错误；单次最多 50 页；`maxChars` 默认 20000、上限 50000（每页）；总响应预算 200000 字符，超出截断并返回 `truncated=true`、`nextPage`。
- `read_document_text` 从 `page_texts` 读取，不重新解析 PDF/EPUB；没有正文缓存时返回可操作错误：「正文尚未索引，请在 GlossNote 书库中建立正文索引后重试」。
- `read_document_text` 的 `pageCount` 取 `documents.page_count`；为 0 时用 `page_texts` 的最大页号兜底，仍为空则按未索引处理。
- `search_pages` 的 snippet 截到 240 字符，避免正文片段占用过多 token。
- 正文关闭时错误文案固定指向设置页「MCP → 允许读取正文」。

### DB 辅助函数

在 `db.rs` 新增，避免复制 SQL：

pub fn get_annotation_in_doc(

- 现有 `search_annotations` / `search_pages` 改为调用 `*_filtered(None, 100)`，保持旧行为。
- `SearchHit` 增加 `kind` 字段（SQL 增选 `a.kind`），前端 `types.ts` 同步；现有 e2e mock 的 SearchHit fixture 补 `kind`。

- `page_texts_range` 按 `page ASC` 返回；页数上限由调用方控制。

### 资源

- `resources/list`：`glossnote://library`，以及最多 20 份最近文档的 `glossnote://doc/<id>`。
- `resources/read`：
  - `glossnote://library`：文档数、标注数、各 kind 数量、`exposeText`、生成时间。
  - `glossnote://doc/<id>`：与 `get_document` 相同的元数据。
- 资源只读元数据，不含正文；未知 URI 返回错误。

### 测试

- `tools::execute` 直接单测：列表过滤/分页、limit 钳制、页码 +1、未知 docId、标注不属于文档、正文关闭错误、正文范围截断。

## 9. M4：笔记存储

### 文件与命令

新增 `src-tauri/src/notes.rs`，`main.rs` 注册命令。

```text
<library>/.glossnote/notes/<docId>.md
```

```rust
#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
pub struct NoteFile {
    pub text: String,
    pub updated_at: i64,
    pub revision: String,
}

pub fn note_path(root: &Path, doc_id: &str) -> Result<PathBuf, String>;
pub fn read_note(root: &Path, doc_id: &str) -> Result<NoteFile, String>;
pub fn save_note(
    root: &Path,
    doc_id: &str,
    text: &str,
    expected_revision: &str,
) -> Result<NoteSaveOutcome, String>;
```

- `note_path` 只接受 `[A-Za-z0-9_-]{1,128}`，拒绝分隔符与 `..`；命令层再查索引确认文档存在。真实 docId 是 64 位 sha256，规则兼容旧测试 id。
- `read_note`：不存在返回 `{text:"", updatedAt:0, revision:""}`；超过 2 MB 或非 UTF-8 返回错误。
- `save_note`：
  1. 读取当前文件算 revision；
  2. 与 `expected_revision` 比较，不一致返回 `Conflict { current }`；
  3. `text.len() > 2MB` 返回错误；
  4. `trim()` 为空则删除文件，返回空 note；
  5. 否则写同目录临时文件，`fs::rename` 替换；失败时按现有 `settings::save` 的「删除目标再 rename」兜底；
  6. 重新读 mtime/revision 返回。
- 把 `settings::save` 的临时文件 + rename 抽成 `pub(crate) fn atomic_write(path, bytes)`，settings 与 notes 共用，避免两套原子写逻辑漂移。
- 进程内串行化：`AppState` 增加 `pub note_write: Mutex<()>`，`save_document_note` 全程持有该锁；不要与 DB 锁嵌套。

## 15. 风险与回退

| 风险 | 触发 | 处理 |
| --- | --- | --- |
| rmcp API/打包不兼容 | M0 `cargo check` 或启动失败 | 回退手写最小 JSON-RPC；工具实现不变 |
| MCP 客户端差异 | Claude Desktop/Cursor 连接失败 | v1 保证一个客户端；其余给配置说明；必要时切 stateful/stateless |
| 端口占用 | 8765 被占用 | 设置页显示错误，允许改端口；启动失败不阻塞应用 |
| 本机恶意进程读 settings | token 明文 | 文档明确；MCP 只读 + 正文 opt-in 为主要缓解；后续系统凭据库 |
| 笔记冲突 | 云盘/外部编辑 | revision 冲突 + 面板内选择；切文档前阻止，避免丢字 |
| 笔记搜索慢 | 大书库 | 2 MB/文件、50 条上限；P2 再上 FTS5 |
| 正文读取过大 | Agent 请求整本 | 50 页/次、200k 字符总预算、per-page maxChars |
| page_texts 缺失 | 未建正文索引 | 明确指引；MCP 不重新解析 PDF/EPUB |
| DB 锁阻塞 UI | 工具查询 | 短查询 + spawn_blocking；禁止跨 await 持锁 |
| localStorage 配额 | 浏览器模式 2 MB 笔记 | 仅开发/测试；文档说明桌面端走文件 |
| 删除文档时笔记残留 | PDF 文件已缺失 | early return 前处理笔记；计入 trashed |
| 版本号交叉 | 0.5.0 未发版 | 先 0.5.0 后 0.6.0；开发期不 bump |
