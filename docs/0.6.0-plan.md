# 0.6.0 技术方案：MCP 接入与文档笔记

> 实施方案：[0.6.0-implementation-plan.md](0.6.0-implementation-plan.md)

## 目标

把 GlossNote 从「带 AI 的阅读器」推进为「本地阅读上下文服务」：

- 外部 Agent（Claude Desktop、ChatGPT 连接器、Cursor 等）通过 MCP 只读访问书库、标注、书签与正文。
- 每篇文档有一份 Markdown 笔记，可以把标注、页码和其他文档作为引用写进去，并跳回原文。
- 复用现有 SQLite、sidecar 与阅读链路，不引入第二套文档/标注数据源。

非目标：本地 Agent 托管（ACP）、MCP 写入标注、完整 Wiki 双链/图谱、笔记多人实时协作、版面分析、移动端。

## 核心决策

1. **MCP v1 只读**：只暴露查询能力，不提供写标注、写笔记、删文档的工具；写入留在应用内完成。
2. **应用内 loopback HTTP MCP**：MCP 服务运行在桌面进程内，只绑 `127.0.0.1`；不单独发布 CLI。默认关闭，用户显式开启。
3. **正文与笔记分级暴露**：文档列表、元数据、标注默认可用；正文搜索与正文读取由 `mcpExposeText` 单独开关控制，默认关闭。笔记读取随 MCP 一起开放，但 v1 不提供笔记写入工具。
4. **笔记是普通 Markdown 文件**：保存在 `.glossnote/notes/<docId>.md`，不塞进 sidecar。SQLite 只在 P1 做可选搜索缓存，文件始终是事实来源。
5. **引用语法保持小而明确**：v1 只支持 `[[annotation:<id>]]`、`[[doc:<id>]]`、`[[doc:<id>#page=N]]`、`[[page:N]]`；不做任意 `[[文件名]]` 解析。
6. **笔记 UI 复用现有侧栏**：新增「笔记」页签和可展开的专注编辑面板，不引入 Dockview 式分屏；侧栏宽度继续可拖动。

## MCP 设计

### 服务与安全

- 端点：`POST http://127.0.0.1:<port>/mcp/<token>`；使用 MCP Streamable HTTP。
- 默认端口 `8765`，冲突时设置页提示并允许修改；端口只绑 loopback。
- 启用时生成随机 token，写入 `settings.json` 的 `mcp.token`；设置页展示可直接粘贴的客户端配置。token 放在路径里，兼容不便自定义 Header 的客户端。
- 拒绝带 `Origin` 头的请求，避免浏览器页面通过 localhost 访问；只接受本机原生 MCP 客户端。
- 不读取任意文件路径；所有 `docId` 必须能在索引中查到，`annotationId` 必须属于该文档。
- 列表/搜索结果有硬上限；正文读取有分页与字符预算。
- MCP 服务不绕过 SQLite 锁：查询走短锁，长文本读取在锁外完成。

### 工具

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `list_documents` | `query?`、`kind?`、`limit?`（默认 50，上限 200）、`offset?` | 瘦字段：id、name、kind、title、author、pageCount、annotationCount、lastPage |
| `get_document` | `docId` | 文档元数据、书签、标注数、最近阅读页 |
| `search_annotations` | `query`、`docId?`、`limit?`（默认 50，上限 200） | 标注命中：docId、annotationId、page、quote、body、color、kind |
| `list_annotations` | `docId`、`page?`、`kind?`、`color?`、`limit?` | 当前文档标注列表 |
| `get_annotation` | `docId`、`annotationId` | 单条标注完整内容 |
| `search_pages` | `query`、`docId?`、`limit?` | 正文片段命中；需要 `mcpExposeText=true` |
| `read_document_text` | `docId`、`pageStart?`、`pageEnd?`、`maxChars?` | 分页正文；需要 `mcpExposeText=true`；`maxChars` 每页默认 20000、上限 50000 |
| `get_notes` | `docId` | Markdown 笔记、更新时间、revision |

- 所有工具声明 `outputSchema`，成功时返回 `structuredContent`；文本块保留简短说明。
- 默认列表不返回正文、摘要或完整批注历史，避免 token 浪费。
- `search_pages` 的 snippet 限制在 240 字符；正文读取必须在设置中显式开启后才可用，错误信息要指向设置项。
- v1 不提供 `write_annotation`、`append_note`、`delete_document`。

### 资源

| URI | 内容 |
| --- | --- |
| `glossnote://library` | 当前书库摘要：文档数、最近文档、标注数、是否允许正文 |
| `glossnote://doc/<id>` | 文档元数据与标注摘要 |

引用 URI 统一为：

```text
glossnote://doc/<docId>?page=<0-based-page>&annotation=<annotationId>
```

P1 再注册 Tauri deep link，让外部客户端点击 URI 能打开应用；v1 先保证 URI 稳定、可复制。

### 配置与生命周期

```json
{
  "mcpServers": {
    "glossnote": {
      "url": "http://127.0.0.1:8765/mcp/<token>"
    }
  }
}
```

- `settings.json` 增加：

```json
{
  "mcp": {
    "enabled": false,
    "port": 8765,
    "token": "",
    "exposeText": false
  }
}
```

- 启用时若 token 为空则生成 32 字节随机十六进制串；关闭后停止监听，token 保留以便下次复用。
- 启动时若 `enabled=true` 则启动服务；端口占用、绑定失败写入状态并在设置页显示错误，不阻塞应用启动。
- 退出/关闭开关时取消监听任务；不留下后台线程。
- 设置页显示：开关、端口、正文开关、运行状态、复制客户端配置、重置 token。
- 依赖优先用 `rmcp`（官方 Rust SDK，`server` + `transport-streamable-http-server` 特性），用 `axum` 挂载 Streamable HTTP 服务；若与 Tauri 运行时或打包冲突，退回手写最小 JSON-RPC 子集，协议面保持不变。

## 文档笔记设计

### 文件与命令

```text
<library>/
└── .glossnote/
    └── notes/
        └── <docId>.md
```

- 纯 UTF-8 Markdown；单文件上限 2 MB；空笔记删除文件，避免书库堆积空文件。
- 写入采用临时文件 + rename；保存前比较 `revision`（内容 sha256），不一致返回冲突，不静默覆盖。
- Rust 命令：

```rust
#[tauri::command]
async fn read_document_note(app: AppHandle, doc_id: String) -> Result<NoteFile, String>;

#[tauri::command]
async fn save_document_note(
    app: AppHandle,
    doc_id: String,
    text: String,
    expected_revision: String,
) -> Result<NoteFile, String>;
```

```rust
#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
struct NoteFile {
    text: String,
    updated_at: i64,
    revision: String,
}
```

- 浏览器模式用 `localStorage` 键 `glossnote:note:<docId>` 提供同样的读写接口，便于 Playwright 覆盖；桌面模式始终走文件。
- 笔记不进入 sidecar，不参与标注历史；P2 再评估是否加入侧车同步或冲突副本。
- 删除文档时笔记文件随文档与 sidecar 一起进回收站；扫描不读取 `.glossnote/notes/`，避免孤儿笔记出现在书库。

### 引用语法

| 写法 | 行为 |
| --- | --- |
| `[[annotation:<id>]]` | 显示标注摘录/颜色；点击跳到对应页并聚焦标注 |
| `[[doc:<id>]]` | 显示目标文档标题；点击打开文档 |
| `[[doc:<id>#page=12]]` | 打开目标文档并跳到第 13 页（页码从 1 展示） |
| `[[page:12]]` | 跳到当前文档第 13 页 |

- 解析器是纯函数，未知 id、非法格式按普通文本显示，不抛异常。
- 渲染时复用现有 `Markdown` 的块级解析，新增 `NoteMarkdown`（或给 `Markdown` 增加 link renderer）；不引入第三方 Markdown 编辑器依赖。
- 编辑器 v1 用 `textarea` + 预览切换 + 600ms 防抖自动保存；`Ctrl/Cmd+S` 立即保存；侧栏笔记页签提供「专注编辑」按钮，打开居中大编辑面板。
- 文档切换、关闭文档、窗口隐藏前 flush 未保存内容；保存失败在笔记面板内显示，不用全局消息覆盖。

### UI

- `sideTab` 增加 `'notes'`，所有格式（PDF/TXT/HTML/EPUB）都显示「笔记」页签。
- 笔记页签内容：
  - 顶部：保存状态、预览/编辑切换、专注编辑。
  - 编辑：`textarea`，等宽字体，支持 `Ctrl+S`。
  - 预览：Markdown 渲染 + 引用 chip。
  - 冲突：显示「文件已在别处修改」与「重新载入 / 覆盖保存」。
- 专注编辑面板复用 `.modal-backdrop`，宽 `min(960px, 92vw)`，高度 `86vh`；Esc 关闭前保存。
- 笔记页签宽度跟随现有侧栏拖拽；不新增分屏布局。

### 搜索与导出（P1）

- 书库搜索增加「笔记」结果组：P1 先用 Rust 扫描 `.glossnote/notes/*.md` 做大小写不敏感子串匹配，结果返回 docId、片段、命中位置；数据量大时再建 FTS5 缓存。
- Markdown 导出增加「文档笔记」章节，放在标注之前或之后由导出选项决定。
- MCP `get_notes` 读取同一文件；P2 再评估带确认的 `append_note`。

## 风险与开放问题

- **MCP 客户端差异**：Claude Desktop、ChatGPT 连接器、Cursor 对 HTTP MCP 的配置方式不同；v1 至少保证一个客户端完整可用，其余给配置说明。
- **rmcp 与 Tauri 打包**：新增 HTTP/异步依赖可能增大安装包；先做 spike，必要时退回最小 JSON-RPC 实现。
- **本地安全边界**：loopback + token 路径 + 拒绝 Origin 能挡住浏览器和普通误连，但本机恶意进程仍可读取 settings；MCP 只读与正文 opt-in 是主要缓解。
- **笔记同步冲突**：v1 只做单文件 revision 冲突检测，不实现跨设备合并；云盘冲突副本与笔记版本历史留到 P2。
- **笔记搜索性能**：P1 用子串扫描，大书库可能慢；超过阈值再切 FTS5。
- **正文预算**：分页读取需要与现有 `page_texts` 缓存/索引配合，避免为了 MCP 重新解析整本 PDF。
