# 产品设计

## 一句话

GlossNote 是一个本地优先的文档阅读与标注客户端：把 PDF 导入书库，在页面上划线、批注，之后再把标注沉淀成可检索、可复习、可被 AI 引用的知识。

中文名暂定「旁注」，英文名 GlossNote。

## 要解决的问题

读长文档时，真正有价值的东西不是“读完了”，而是你当时划出的那句话、写下的那个想法。它们通常散落在：

- PDF 阅读器的高亮里，换一个阅读器就没了；
- 浏览器书签和稍后读里，原文改版后锚点全废；
- 笔记软件里，和原文彻底脱节，回头找不到出处；
- 脑子里，两周后只剩一个模糊印象。

GlossNote 要保证三件事：**标注不丢、能回到原文、能继续被使用**。

## 目标用户

第一阶段只服务一类人：**自己**——需要读论文、教材、报告、长文，并且愿意为“读完之后还能用”付出一次整理成本的人。

不优先考虑团队协作、教师批改、企业知识库等场景；这些会显著改变权限、同步和部署模型。

## 核心闭环

```
导入文档 → 阅读 → 划线/批注 → 沉淀为卡片 → 复习 / 向 AI 提问
              ↑                              │
              └──────── 引用回到原文 ←────────┘
```

闭环里最关键的是最后一步：任何沉淀出来的内容都能一键回到它来自的那一行字。做不到这一点，产品就退化成“另一个 PDF 阅读器 + 另一个笔记软件”。

## 产品形态

- **桌面客户端**，Tauri 2 + React，Windows 优先。
- 主窗口内两个视图：**书库**（封面列表、搜索、标签）与**阅读器**（PDF、标注侧栏）。
- 导入即入库：用户通过按钮或拖拽把 PDF 放进客户端，文件复制到书库目录，之后不需要再碰文件系统。
- 本地优先：默认不注册、不联网；云同步是可选项。
- 未来可选一个全局快捷键的速记浮窗，但不在第一版范围内。

## 非目标（至少 1.0 之前）

- 多人协作、评论、权限体系。
- 通用笔记编辑器（不跟 Obsidian / Notion 正面竞争）。
- 移动端与手写输入（坐标和数据结构预留，但不实现）。
- 扫描件 OCR、加密 PDF、DRM EPUB。
- 在线文档托管服务。

## 体验原则

1. **标注必须保真。** 缩放、换窗口、重启、换设备后，高亮仍落在同一行字上。做不到就不要发布。
2. **数据必须可带走。** 标注是明文 JSON，书库是普通 PDF 目录；删掉应用也能用别的工具继续读。
3. **离线是默认状态。** 联网只用于可选的同步和 AI，不联网时功能不降级。
4. **AI 必须可溯源。** 每个 AI 结论都能点回原文或你的标注，否则不给结论。
5. **阅读界面不打扰。** 标注工具在选中文字时出现，其余时间让位给正文。

## 竞品与差异

| 产品 | 强项 | 我们不走的路 |
| --- | --- | --- |
| Readwise Reader / Matter | 稍后读体验、导出到笔记软件 | 文件托管在云上，产品关停则数据迁移成本高（Omnivore、Pocket 已关停） |
| Zotero 7 | 学术 PDF 标注、文献管理 | 只服务学术流程，不做通用阅读与知识沉淀 |
| Hypothes.is | W3C 标注模型、网页锚定开源实现 | 只做网页，不做本地文档与知识库 |
| Obsidian / Logseq | 本地优先、Markdown 可迁移 | 标注是插件能力，PDF 体验不是核心 |
| MarginNote / LiquidText | 摘录、脑图、空间组织 | 封闭生态，平台受限，数据不易迁移 |

差异点：**本地优先 + 标注可迁移 + 基于自己标注的 AI**。三者同时做到的产品目前没有。

## 商业化与风险

- 自用优先，功能稳定后再考虑商业化；商业化不改变“数据归用户”的底线。
- 阅读器 + 收藏这个赛道付费意愿低、运营成本高，护城河只能是标注数据和沉淀结果，而不是内容托管。
- 主要风险：扫描件与加密文档、云盘冲突副本、跨设备同步的一致性、AI 成本与延迟。
- 网页剪藏涉及版权，做多格式时只保存用户自己阅读的正文与标注，不提供内容分发。

- 中文：暂定「旁注」，与 gloss（页边解释）对应。
