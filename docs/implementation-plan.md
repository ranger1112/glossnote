## 0.5 云同步（已完成）

采用“零代码”路线：书库放在云盘同步目录，应用负责识别并合并 sidecar 冲突副本；不做账号与服务端同步。

实现：

1. **书库位置 UI**：书库页显示当前目录与上次扫描时间；「书库位置」调用原生目录选择器，确认后写入 `settings.json`、清空旧索引并扫描新目录。运行时通过 `RwLock<PathBuf>` 切换，不需要重启。
2. **冲突识别**：扫描 `.glossnote/annotations/*.json` 的全部文件（不仅是 `<docId>.json`），解析后按文件内的 `docId` 分组，兼容 OneDrive、Dropbox、Syncthing、Nextcloud 等不同冲突命名。
3. **按记录合并**：同一 `annotation.id` 按 `updatedAt` 新者胜；墓碑同样参与比较；规范文件先处理，时间戳相同时规范文件优先，保证结果确定。
4. **归档原文**：合并成功后，把非规范的冲突副本移到 `.glossnote/conflicts/`，保留原始 JSON 便于追溯；重名时追加毫秒时间戳。
5. **重复 PDF**：同一内容哈希的多个 PDF 只索引一个，其余保留文件但计数提示，不自动删除用户文件。
6. **可见状态**：`ScanReport` 返回合并条数、归档数、重复 PDF、无效 sidecar 与扫描时间；书库页展示，并提供手动「重新扫描」。

验收证据（2026-10-27，WebView2 CDP + 文件检查 + Rust 单测）：

- 模拟云盘冲突副本：同一条标注被改成更新版本，另一个副本新增 1 条；扫描后状态栏显示「合并 2 条，归档 1 个冲突副本」，阅读器里两条批注正确。
- 归档文件出现在 `.glossnote/conflicts/`，原冲突文件从 `annotations/` 消失；规范 sidecar 回写为合并后的 2 条。
- 关闭应用后写入新冲突副本，重启自动合并 2 条并归档 1 个，说明启动扫描路径生效。
- 通过原生目录对话框切换书库：路径、`settings.json`、空书库状态同步更新；切换回原目录后，从 PDF + sidecar 重建 1 份文档、2 条标注。
- 复制一份同名同内容的 PDF 后扫描：文档数不变，报告「1 份重复 PDF 已忽略」。
- 墓碑冲突单测、冲突合并与归档单测通过；`cargo test` 4/4，`npm test` 7/7，`npm run build` 通过。

已知差距：

- 没有自动定时扫描；依赖启动与手动「重新扫描」，云盘在应用运行中写入的新冲突需要手动刷新。
- 冲突副本只按记录合并，不提供逐字段 diff 或人工选择保留哪一版；同时间戳的冲突按文件路径顺序取舍。
- 重复 PDF 不会自动清理；需要用户自行决定删除哪一份。
- 书库索引是单库模型，切换根目录会清空 SQLite 并重建，不做多库并存。

## 0.6 知识沉淀（已完成）

任务：标注转卡片、双向链接、FSRS 调度、复习界面。

实现：

1. **卡片模型**：`cards` 表 + sidecar 的 `cards` 字段；卡片记录标题、内容、来源标注/文档/页码、链接、状态与 FSRS 记忆参数。一条标注对应一张卡片，卡片 id 固定为 `card-<annotationId>`，重复保存是幂等的。
2. **从标注制卡**：标注卡片新增「制卡」按钮，预填原句或批注正文；编辑器可改标题、内容并选择要链接的卡片。已有卡片时入口变为「卡片」，打开同一编辑器修改。
3. **双向链接**：卡片保存 `links`（出链 id）；列表查询时反算 `backlinks`。详情弹窗可点击链接与反向链接互相跳转；目标已删除时显示为不可点的「已删除的卡片」。
4. **FSRS-4.5**：Rust 纯函数实现默认权重的 FSRS-4.5（again/hard/good/easy），保存 stability、difficulty、reps、lapses、lastReviewedAt、dueAt；复习前展示四档预计间隔，复习后按新记忆状态排期。again 固定 10 分钟，其余至少 1 天（上限 10 年）。
5. **复习界面**：顶栏新增「复习」视图；按到期时间给出队列，显示来源原句、打开原文入口、四档评分与间隔；队列为空时显示下一张到期时间；下方列出全部卡片与状态（新卡/到期/已排期/来源失效）。
6. **来源失效**：删除标注只写墓碑，并把来源卡片标记为 `orphaned`，保留卡片内容与复习记录；跨设备删除通过 sidecar 墓碑合并后同样触发。
7. **同步**：`write_sidecar` 写入该文档的卡片（含卡片墓碑）；扫描时按卡片 `updatedAt` 与标注同样的 LWW 规则合并，`ScanReport` 增加 `mergedCards`。

验收证据（2026-10-27，WebView2 CDP + 文件检查 + Rust 单测）：

- 从标注制卡：预填标题/正文，保存后侧栏显示「卡片 · 新」，sidecar 出现卡片记录。
- 复习：新卡显示「重来 10 分钟 / 困难 28 小时 / 良好 3 天 / 容易 15 天」；点「良好」后卡片变为「已排期」，复习次数 1，`dueAt` 约为 3 天后，sidecar 中 stability=3.1262。
- 双向链接：第二张卡片链接第一张后，第一张卡片的详情显示反向链接「第二张卡片」，点击可跳转。
- 删除来源标注后，卡片状态变为 `orphaned`，内容与链接保留，侧栏入口消失；复习页仍可查看、编辑和复习，并明确提示来源失效。
- 删除卡片写墓碑；sidecar 保留 `deleted: true`，列表不再显示。
- 模拟云盘卡片冲突副本：重新扫描后卡片标题采用较新版本，冲突副本归档到 `.glossnote/conflicts/`。
- 删除 `library.db` 后重启：从 sidecar 重建 2 张卡片，包含失效率、复习次数与遗忘次数。

已知差距：

## 0.7 AI（已完成）

任务：划词解释（带上文窗口）、基于标注/文档的检索问答、引用跳转。

实现：

1. **默认关闭 + 显式配置**：`settings.json` 增加 `ai` 配置（enabled / provider / model / baseUrl / apiKey）。AI 设置弹窗支持 Anthropic 与 OpenAI 兼容服务（Ollama、LM Studio 等），可保存并测试连接；切换服务商会清除旧 Key，避免把上一家的 Key 发到新地址。
2. **两条请求路径**：Rust 侧 `reqwest` 直接调用 Provider，不经过 WebView，因此不需要放宽 CSP；Anthropic 用 `/v1/messages` + `x-api-key` + `anthropic-version`，OpenAI 兼容用 `/v1/chat/completions`。
3. **划词解释**：选中文字后的浮动栏增加「AI 解释」，发送选段、前后文与页码；回答下方给出可点击的页来源。
4. **本地全文索引**：前端用 pdf.js 逐页提取文字，后端按约 900 字切块、120 字重叠写入 SQLite `chunks` 表；索引只在本机进行，不联网，扫描件会提示无文字。只有用户点击「提取全文」才建立索引。
5. **可溯源问答**：问题按中文二元组 + 英文词做词法检索，从当前文档的页面切块与标注中选最多 6 段原文 + 4 条标注，编号后交给模型；回答返回 citations，界面底部列出 `[n] 第 N 页 · 原文/标注`，点击跳回对应页。
6. **总结**：「总结全文」按页均匀采样切块 + 标注；「总结我的标注」只使用当前文档的标注。两者都要求引用来源。
7. **失败可见**：未启用、缺 Key、HTTP 错误、超时、空响应都直接显示；不自动重试、不吞错。

验收证据（2026-10-27，WebView2 CDP + 本地 mock AI 服务 + 检查请求日志）：

- 通过设置弹窗保存 OpenAI 兼容配置并「保存并测试连接」，返回 `OK`；设置写入 `settings.json`，旧 `libraryDir` 保留。
- 打开示例 PDF 的 AI 面板，点击「提取全文」后状态变为「全文已索引 · 2 段」，`documents.text_indexed_at` 置位。
- 提问「文档的核心观点是什么？」返回回答，来源列表包含第 1 页原文、第 2 页原文与第 1 页标注；点击 `[2]` 后阅读器滚到第 2 页（`scrollTop` 1012.8）。
- 选中正文点「AI 解释」，面板显示选段与页来源。
- 切换到 Anthropic 配置后测试连接成功；mock 日志确认请求走 `/v1/messages`，携带 `x-api-key`、`anthropic-version`，正文包含检索资料。
- 「总结全文」与「总结我的标注」均返回带来源的回答。
- sidecar 中不含 API Key；Key 只出现在本机 `settings.json`。
- `cargo test` 17/17（含切块、检索词、排序、来源配额）、`npm test` 7/7、`npm run build` 通过。

已知差距：

- 检索是词法匹配，没有向量嵌入；同义改写或跨语言提问的召回有限。
- 对话只在当前面板会话内保留，关闭后不落盘；流式输出已做，长回答无需等完整返回。跨文档问答与向量检索未实现。
- 引用依赖模型在正文中写 `[n]`；界面只保证来源列表可点回原文，不解析正文里的编号。
- API Key 明文保存在本机应用数据目录；没有接入系统凭据库。
- 只索引当前文档；跨书库/跨文档问答未实现。AI 开关是全局的，尚未做到逐文档授权。
- 扫描件没有文字层时只能基于手工标注提问。

## 1.x 批注完整度（已完成）

## 大文档性能（已实测）

测试对象：90 MB / 529 页 PDF，单页基准 1519×2270，适宽 57%，DPR 1.25。

| 项目 | 实测 |
| --- | --- |
| Rust `open_document`（DB + sidecar 合并） | 24 ms |
| 取 PDF 字节（asset protocol） | 599 ms |
| 打开到第一页文字层 | 4.0–5.2 s（波动，未改动） |
| 跳到最后一页 / 回第一页 | 1.3–1.6 s / 约 2.1 s（基本不变） |
| 全库稀有词搜索（冷 / 命中缓存） | 6.1 s / 0.3 s（另需约 0.5 s 读缓存） |
| 连按 5 次缩放（57% → 182%） | 约 0.7 s，只重绘一次（原约 2.5–3 s） |
| 182% 时活动画布 | 3 页、约 4800 万像素（约 192 MB 原生画布内存） |

已做：

- `page_texts` 表缓存逐页原文，重复搜索直接读 SQLite。
- 缩放防抖 140 ms，只渲染最终比例。
- ~~跳页时当前页优先，相邻页延后 150 ms~~：最早把优先级放进渲染 effect 依赖，会让滚动中的可见页面被清空重绘，已移除；现在只让相邻页首次挂载延后 120ms，优先级不参与 effect 依赖。

剩余瓶颈：

- 打开时间主要花在 pdf.js 解析 90 MB 文档与首屏渲染，Rust 侧不是瓶颈；需要渐进渲染或更低的首屏分辨率才有明显改善。
- 远距跳页需要重新取页与渲染大页面，当前页优先只降低资源争抢，没有改变单页渲染成本。

## 0.4.0 多格式（已完成）

TXT、HTML、EPUB 都映射成统一的 unit 分页模型：阅读器、标注、书签、进度、页内查找与正文索引共用同一套上层逻辑；PDF 保持 pdf.js 渲染。锚定统一走 `AnchorStrategy` 的文本偏移策略。

- **TXT（已完成）**：按换行边界切页；UTF-8 优先、GB18030 兜底。
- **HTML（已完成）**：Readability 提取正文，清理脚本、事件属性与远程图片；标题生成目录；相对图片按导入源目录解析；导入的是本地文件，本身就是冻存快照。
- **EPUB（已完成）**：JSZip 解析 container/OPF/spine，按章节分页；zip 内图片内联为 data URL；标题生成目录；标注额外写入章节内 DOM 路径定位符（CFI 风格），文本定位失效时优先用它回放。
- **窗口化与封面（已完成）**：流式文档只挂载当前页附近几页，其余用实测/估算高度占位；封面用标题与作者生成。
- 暂未做：网页 URL 剪藏、EPUB 原生封面提取、与第三方阅读器的完整 CFI 互操作。

验收：三种格式都能高亮、批注、重开复原；TXT / HTML / EPUB 均有浏览器端 e2e 覆盖，长 TXT 有窗口化用例。

## 阻塞与风险

| 项 | 影响 | 处理 |
| --- | --- | --- |
| Rust 不在系统 PATH | 直接跑 npm/tauri 会找不到 cargo | 网关脚本先加载 `_env.cmd`，并直接调用 `.bin\tauri.cmd`；见 [build.md](build.md) |

| 大 PDF 经 IPC 传输 | 内存与卡顿 | 先限 50 MB，后续 asset protocol |
| 扫描件无文本层 | 无法高亮 | 明确提示；OCR 推迟 |
| 首次扫描大书库需要逐文件哈希 | 启动变慢 | 仍为启动时同步扫描；后续改为后台扫描 + 进度提示 |
| 书库位置尚无 UI | 只能手改 settings.json | 目录选择器推迟到 0.5 前后 |
| 标注搜索用 LIKE 子串匹配 | 大书库变慢 | 正文已走 FTS5；标注数量有限，后续按需建索引 |
| FSRS 无个性化权重 | 排期不完全贴合个人记忆 | 先用默认参数；积累复习日志后再评估优化器 |
| AI 词法检索召回有限 | 同义问题可能找不到原文 | 先保证可溯源；后续评估本地嵌入或混合检索 |
| API Key 明文保存 | 本机其他程序可能读取 | 应用数据目录按用户隔离；后续评估系统凭据库 |
| 云盘冲突副本 | 标注重复/丢失 | 0.5 已按 docId 识别、按记录合并并归档 |
| AI 成本与幻觉 | 信任受损 | 强制引用；默认关闭；本地模型可选 |
